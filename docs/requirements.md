# Требования к информационному ресурсу «Прокат автомобилей»

## 1. Функциональные требования (ФТ)
Каждое требование определяет обязательное действие системы для трех ролей: Гость, Клиент, Менеджер.

| ID | Описание требования | Источник | Приоритет | Критерий приёмки |
| :--- | :--- | :--- | :--- | :--- |
| **FR-01** | Система должна отображать каталог доступных автомобилей с фильтрацией по классу (Эконом, Комфорт, Бизнес). | Бизнес-процесс | Must (Критический) | В каталоге работают фильтры, скрывая неподходящие машины. |
| **FR-02** | Система должна позволять пользователю регистрироваться с указанием ФИО, телефона, email и стажа вождения. | Пользователь | Must (Критический) | Создается запись в БД, данные валидируются. |
| **FR-03** | Система должна позволять авторизованному клиенту выбирать даты аренды через интерактивный календарь. | Пользователь | Must (Критический) | Даты блокируются для других, овербукинг исключен. |
| **FR-04** | Система должна автоматически рассчитывать итоговую стоимость проката на основе выбранных дней и тарифа авто. | Бизнес-процесс | Must (Критический) | Цена выводится на экран перед подтверждением брони. |
| **FR-05** | Система должна позволять менеджеру изменять статус автомобиля (Доступен, В прокате, На ТО, В ремонте). | Менеджер | Must (Критический) | Статус меняется в админ-панели и обновляет каталог. |
| **FR-06** | Система должна позволять клиенту отменять активное бронирование в личном кабинете не позднее чем за 24 часа. | Пользователь | Should (Важный) | При отмене статус брони меняется на «Отменено», машина освобождается. |
| **FR-07** | Система должна отправлять клиенту email-уведомление с подтверждением успешного бронирования и номером заказа. | Бизнес-процесс | Should (Важный) | Письмо поступает на указанную почту в течение 1 минуты. |
| **FR-08** | Система должна позволять менеджеру просматривать полный список активных заказов на текущие сутки. | Менеджер | Must (Критический) | Выводится таблица с сортировкой по времени выдачи авто. |
| **FR-09** | Система должна блокировать возможность бронирования для пользователей со стажем вождения менее 2 лет. | Служба безоп. | Must (Критический) | Выводится предупреждение, кнопка бронирования становится неактивной. |
| **FR-10** | Система должна позволять клиенту оставлять текстовый отзыв и оценку (от 1 до 5) автомобилю после завершения аренды. | Пользователь | Could (Желательный)| Отзыв привязывается к карточке машины и виден другим. |
| **FR-11** | Система должна позволять менеджеру формировать отчет по выручке и занятости автопарка за выбранный месяц. | Директор | Should (Важный) | Генерируется табличная форма с итоговыми суммами. |
| **FR-12** | Система должна автоматически переводить просроченное бронирование в статус «Архив», если клиент не забрал авто. | Бизнес-процесс | Could (Желательный)| Автоматический скрипт обновляет БД раз в сутки. |

## 2. Нефункциональные требования (НФТ)
- **NF-01 (Безопасность):** Все пароли пользователей должны храниться в базе данных в зашифрованном виде (хэш-функции).
- **NF-02 (Производительность):** Время отклика системы при поиске автомобиля в каталоге не должно превышать 2 секунд.
- **NF-03 (Надежность):** Система должна быть доступна 99% времени в месяц, исключая плановые технические работы.
- **NF-04 (Интерфейс):** Веб-ресурс должен иметь адаптивный дизайн и корректно отображаться на мобильных экранах со смартфона.
